# dsh-wechat-mp 操作手册

> 面向使用者。你**只需要在 dsh web 的对话框里说人话**，不需要记命令。
> 插件名：`dsh-wechat-mp` · 工具前缀：`wechat_*` / `wechat_mp_*`

---

## 一、先搞清楚：三种用法，两种"要不要扫码"

| 用法 | 你说什么 | 要扫码吗 | 产物 |
|---|---|---|---|
| **① 抓单篇** | 给一个文章链接 | **不用** | 一篇 Markdown + 本地图片 |
| **② 抓一批** | 给一份清单文件 | **不用** | 清单里所有文章的 Markdown |
| **③ 抓某个号** | "把这个号的文章都抓下来" | **要（只扫一次）** | 先枚举出清单，再抓正文 |

关键区别：

- **①②** 靠的是"文章正文页游客就能看"，**永远不用登录**
- **③** 里只有**"枚举清单"**这一步需要登录；正文还是走 ①② 那条路
- 所以 ③ = 扫码 → 拿到清单 → 然后和 ② 完全一样

> **硬前提**：扫码用的微信号必须是某个公众号的**管理员或运营者**。没有自己的公众号，③ 走不通（①② 不受影响）。

## 二、三个场景，照着说就行

### 场景 ①：我只想抓一篇文章

直接把链接丢给它：

```
帮我抓这篇文章：https://mp.weixin.qq.com/s/xxxxxxxx
```

它会调 `wechat_fetch_article`，产出：

```
<输出目录>/<文章标题>/<文章标题>.md
<输出目录>/<文章标题>/images/image_001.png …
```

**留意返回里的"内容可能不完整"提示**：付费文章只能抓到试读片段，插件会明确告诉你，
不会骗你说抓成功了。

---

### 场景 ②：我有一批链接要抓

**方式 A（推荐）—— 让它自己建清单**

```
把这几个链接批量抓下来：
https://mp.weixin.qq.com/s/aaa
https://mp.weixin.qq.com/s/bbb
```

**方式 B —— 你自己写清单文件**（可以混不同公众号、甚至混不同来源的网站）

在工作区根目录建 `url-list.json`：

```json
[
  { "url": "https://mp.weixin.qq.com/s/aaa", "source": "wechat" },
  { "url": "https://mp.weixin.qq.com/s/bbb", "source": "wechat" },
  { "url": "https://某博客.com/post/1", "source": "blog" }
]
```

然后说：

```
把 url-list.json 里的文章都抓下来
```

它会调 `wechat_fetch_list`。**已经抓过的会自动跳过**（`status: done`），所以中断了再跑一次就行。

想先看看还剩多少没抓：

```
看一下清单现在什么状态
```

### 场景 ③：我要抓某个公众号的全部文章（需要扫码）

分四步，但**你只需要说三句话**。

#### 第 1 句：扫码登录

```
帮我登录微信公众号后台
```

它调 `wechat_mp_authorize`，然后：

- 对话里会出现一张**扫码卡片**（二维码就在里面，每 1.5 秒自动刷新状态）
- 同时二维码也会**写到文件**里作为退路：
  `<输出目录>/.dsh-wechat-mp/qrcode.png`

**用微信扫它，手机上点确认。** 卡片会依次显示：请扫码 → 已扫码请在手机确认 → 已登录。

> 看不到卡片？打开上面那个 PNG 文件扫也一样。
>
> 提示"二维码已过期"是正常的 —— 插件会自动换一张新图，你扫新的那张就行。
>
> 登录态会**保存下来**，下次同一个号不用再扫。

#### 第 2 句：找号

```
搜一下「公众号名字」
```

返回候选列表（昵称 / 微信号 / 简介）。挑一个确认就行。

#### 第 3 句：枚举

```
把这个号 2026 年之后的文章都列出来，写进清单
```

它能识别的说法（直接说中文即可）：

| 你想做的 | 说法举例 |
|---|---|
| 只要某段时间的 | "2026 年 1 月之后的"、"最近三个月的" |
| 只要原创 | "只要原创的" |
| 按关键词筛 | "标题里有 AI 的" |
| 按合集筛 | "合集《xxx》里的" |
| 排除已删除 | 默认就排除了 |
| 只列不抓 | "先只列出来给我看看" |
| 列完直接抓 | "列出来然后直接抓正文" |

#### 第 4 句：抓正文

枚举完它会说"可以下一步用 `wechat_fetch_list`"。你说：

```
开始抓正文
```

## 三、产出落在哪（重要）

**默认落在哪里**取决于下面这个优先级（从高到低）：

```
① 你当次明确指定的路径        例："抓到 /data/articles"
② 你在界面/对话里设过的路径   例："把输出目录设成 ~/articles"
③ 插件配置里的 outputRoot
④ 当前会话的工作区下的 output/
⑤ dsh 进程的启动目录下的 output/   ← 兜底
```

**怎么看现在用的是哪个**：

```
看一下输出目录配置
```

它会告诉你路径**和来源**。如果你看到"来源：进程工作目录（兜底）"，说明它落在了
dsh 的启动目录里（通常是你的用户主目录），**一般不是你想要的** —— 这时它会主动提示你改。

**改法**（二选一）：

- **只改这一次**（当场说）：
  ```
  把输出目录设成 /Users/你/项目/output
  ```
- **永久改**（编辑插件配置）：在 `~/.dsh/profiles/web/cordis.patch.yml` 里加：

  ```yaml
  - id: wechat-mp
    config:
      outputRoot: /Users/你/项目/output
  ```

  （这个文件是**你自己**的 patch 层，插件不会去改它。）

**目录结构**有两种，用配置里的 `layout` 切：

- `flat`（默认）：`<输出根>/<文章标题>/<文章标题>.md`
- `byAccountDate`：`<输出根>/<公众号名>/<年-月>/<年-月-日>_<标题>/`

## 四、清单文件（`url-list.json`）

这是**枚举与抓取之间的唯一交接点**，也是断点续爬的依据。

每条长这样：

```json
{
  "url": "https://mp.weixin.qq.com/s/xxxxxxxx",
  "source": "wechat",
  "status": "pending",
  "aid": "2247483…",
  "title": "文章标题",
  "publish_time": "2026-09-21 21:25:00",
  "is_pay_subscribe": false
}
```

- `status`：`pending` 待抓 → 抓完变 `done` / 失败变 `failed`
- 后面几个是插件加的**扩展字段**：抓之前你就能看到标题、时间、是不是付费文
- **重复枚举不会重复添加**（按"来源 + 文章 ID"去重）
- **已删除的、视频/图片类文章不会被写进待抓列表** —— 抓了也拿不到正文，插件会告诉你排除了几条

## 五、常见问题

**Q：为什么抓下来的正文明显不全？**
大概率是付费订阅文章或非图文类。插件会在返回里标"内容可能不完整"并说明原因。
这类文章**登录了也拿不到全文**（正文在单独的付费接口里），不要以为是登录态的问题。

**Q：提示"登录已失效，请重新授权"？**
后台会话过期了。重新说一句"帮我登录微信公众号后台"扫一次即可。
登录态**过期判断完全以服务端返回为准**，不看本地时间，所以不会出现"明明还能用却让你重扫"。

**Q：提示"请求过于频繁"？**
微信的风控。插件会自动退避重试；如果持续失败，把配置里的 `pageDelayMs`（默认 3000 毫秒）
调大一些。**不建议调小** —— 风控的代价是不对称的，严重时会影响你的公众号。

**Q：枚举到一半我关掉了，会白干吗？**
不会。已写入清单的条目都在，重新枚举会自动跳过重复项。

**Q：两个会话同时抓会不会打架？**
不会丢数据。清单的读改写走**跨进程文件锁**；如果撞上了会等待，超过 30 秒会明确报错并告诉你是谁占着。

**Q：我不想让它抓某些文章？**
抓之前直接编辑清单（把 `status` 改成别的值，或删掉那几条）即可 —— 这就是把枚举和抓取分开的好处。

**Q：产物我想进知识库 / 做检索？**
Markdown + 本地图片就是为这个准备的。另外 `is_pay_subscribe`、`publish_time`、`album_names`
这些字段都在清单里，建索引时可以先用它们筛。

## 六、一句话速查

```
抓一篇     →  「帮我抓这篇文章：<链接>」
抓一批     →  「把 url-list.json 里的都抓下来」
看状态     →  「看一下清单现在什么状态」
扫码登录   →  「帮我登录微信公众号后台」
找号       →  「搜一下「公众号名」」
枚举       →  「把这个号 2026 年之后的文章列出来，写进清单」
改输出目录 →  「把输出目录设成 <路径>」
看当前配置 →  「看一下输出目录配置」
退出登录   →  「退出公众号登录」
```

## 七、给你的模型看的两条约定

如果你在调 prompt 或写自动化，知道这些更省事：

1. **带 `mp` 的工具都需要登录态**，不带的都不要。
   `wechat_mp_*` → 需要先 `wechat_mp_authorize`；`wechat_fetch_*` → 直接可用。
2. **枚举和抓取是两步**。`wechat_mp_sync_account` 只写清单（除非你让它 `fetchAfterSync`），
   正文由 `wechat_fetch_list` 抓。这样设计是为了让你能在"抓之前"先审一遍清单。
