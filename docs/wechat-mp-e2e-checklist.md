# dsh-wechat-mp 手动 E2E 验证清单

> 面向使用者。**按顺序做**，每步都写了"说什么 / 预期看到什么 / 失败了给我什么信息"。
>
> 设计原则：**从最不容易失败的排到最难的**。前面几步不依赖浏览器、不依赖扫码 ——
> 如果第 1 步就挂了，说明是插件加载问题，跟微信、跟浏览器都无关，排查范围小得多。

---

## 准备：启动服务

**在你自己的终端**（不要在 WorkBuddy / 其他 Node 宿主的 shell 里）：

```bash
npx --yes @deepseek-ai/dsh web
```

它会打印一行带 token 的地址，浏览器打开它。

**启动前建议先跑一次环境自检**（10 秒，能提前排掉最常见的一个坑）：

```bash
cd /Users/taurus/0-ws/00-coding-repo/git-repo/spider-claw
./node_modules/.bin/tsx scripts/probe/l2-camoufox-host.ts
```

- 打印出「✓ P0-13 通过」→ 浏览器可用，第 4 步大概率没问题
- 报 `SIGTERM` / exit 137 / 卡住 → **浏览器在这台机器上跑不起来**，第 4 步一定失败，
  先别往下做，把输出发我

---

## 第 0 步 · 确认插件装上了（不需要扫码、不需要浏览器）

**看设置**：左下角「设置」→「插件」→ 搜索框输入 `wechat`

**预期**：全局插件下有 1 个 —— `wechat-mp`，绿色「已启用」，「运行状态：运行中」

**失败的话**（列表里没有）：把「打开配置文件」的内容发我，并贴一下启动日志里的报错。

---

## 第 1 步 · 工具注册与最基础的调用（不需要扫码、不需要浏览器）

**说**：

```
看一下输出目录配置
```

**预期**：返回一张表或一段文字，含输出根目录、清单文件、凭据文件、落盘布局、翻页间隔。
如果显示「来源：进程工作目录（兜底）」，会**额外多一段 ⚠️ 提示**告诉你产物落在了启动目录。

**这一步验证的是**：插件加载成功 + 工具注册成功 + 模型能识别并调用。

**失败的话**：贴一下模型的回答原文。

---

## 第 2 步 · 另外两个不需要前置条件的工具

**说**：

```
看一下公众号插件的登录状态
```

**预期**：明确回答「无登录态」（还没扫码，这是对的），并显示清单路径与输出根目录。

**说**：

```
看一下清单现在什么状态
```

**预期**：如果工作区里没有 `url-list.json`，它会说读不到 —— **这也是正确行为**，不是 bug。

---

## 第 3 步 · 客户端卡片渲染（不需要扫码、不需要浏览器）★ 之前没验证过

这一步是**唯一能验证"界面卡片"的**，之前只验证到"bundle 被宿主正确服务"。

**说**：

```
看一下输出目录配置
```

**然后看对话里那个工具调用的位置**，除了文字，**应该还有一张卡片**（面板样式），
里面是输出根目录 / 清单文件 / 凭据文件 / 落盘布局 / 翻页间隔，以及一个「复制输出路径」按钮。

**预期**：看到那张卡片，点「复制输出路径」能复制成功。

**如果只看到纯文字、没有卡片**：说明客户端半没加载或注册没生效。请告诉我：

1. 浏览器控制台（F12 → Console）里有没有报错
2. 有没有 `dsh-wechat-mp` 相关的 warning

> 参考：不通过也不算致命 —— 宿主里已经确认这个包进了启动图、bundle 也能正确取到。

---

## 第 4 步 · 改输出目录（不需要扫码、不需要浏览器）

**做之前先想好**：你希望产物落在哪，比如 `/Users/taurus/0-ws/00-coding-repo/git-repo/spider-claw/output`

**说**：

```
把下载的输出目录设成 <你的路径>
```

**预期**：返回新的路径 + 来源「来自本次工具调用的参数」+ 是否已持久化。

**再验证一次**：重复第 1 步的「看一下输出目录配置」，应该显示新路径。

---

## 第 5 步 · 抓一篇文章（不需要扫码，**需要浏览器**）★ 上次就卡在这

**说**：

```
帮我抓这篇文章：https://mp.weixin.qq.com/s/oy49MaX30Vk5mGWY16vzKA
```

（换成你想抓的任意一篇也行）

**预期**：

- 第一次会**明显慢**（Camoufox 冷启动一个 Firefox + 渲染页面 + 逐张下载图片），
  **30~90 秒是正常的**
- 完成后返回：Markdown 路径、标题、作者、发布时间、本地图片张数
- 产物落到第 4 步设的目录：`<输出目录>/<文章标题>/<文章标题>.md` + `images/`

**如果卡住不动**：**最多等 120 秒**，之后会自动报错（这是我加的超时守卫）。
报错信息里会带上排查步骤 —— 把那整段发我。

**如果报错**：把完整错误原文发我，尤其注意有没有 `SIGTERM` / `exit 137` /
`Target crashed` / `Failed to initialize sandbox` 这类字样。

---

## 第 6 步 · 扫码授权（**需要扫码**）

**说**：

```
帮我登录微信公众号后台
```

**预期**：

1. 对话里出现一张**扫码卡片**（二维码 + 状态文字），每 1.5 秒自动刷新
2. 同时二维码也写到了文件：`<输出目录>/.dsh-wechat-mp/qrcode.png`
3. 你用微信扫它 → 手机上点确认 → 卡片变成「已确认，正在登录」→「已登录：<昵称>」

**顺带验证 P0-9**：在浏览器里直接访问 `http://127.0.0.1:3080/wechat-mp/qr`
应该能看到二维码图片（不是 404）。

**如果没有卡片但二维码文件有**：打开那个 PNG 扫也能完成授权 —— 告诉我一声，说明卡片没渲染。

**如果二维码本身就取不到**（报错说 PNG 不合法 / HTTP 失败）：这是**最有价值的失败信息** ——
说明微信的登录接口变了。

---

## 第 7 步 · 搜号 + 枚举（**需要扫码**）

**说**：

```
搜一下「某个公众号的昵称」
```

**预期**：候选列表（昵称 / 微信号 / 简介）。

**说**：

```
把这个号 2026 年之后的文章列出来，写进清单
```

**预期**：返回发现了多少篇、新入列多少、重复跳过多少、排除了多少（已删除 / 视频图片类）。
清单文件里应该出现对应条目。

**顺带验证 P0-1（关键）**：这一步如果真的拿到了文章列表，就说明
**`appmsgpublish` 接口还活着** —— 这是整个方案里最后一个没验证的硬门槛。

**如果报错**：把 `ret=` 那串数字和 `err_msg` 原文发我。这是最有价值的信号。

---

## 第 8 步 · 端到端闭环（不需要扫码，需要浏览器）

**说**：

```
开始抓正文
```

或者：

```
把 url-list.json 里的文章都抓下来
```

**预期**：逐篇抓取，产出 Markdown + 图片；清单里的 `status` 从 `pending` 变成 `done`。
中断了再跑一次会自动跳过已完成的。

---

## 验证结果怎么给我

按这个格式最省事：

```
第几步 · 说了什么 · 看到什么（或错误原文） · 卡了多久
```

**最关键的三个信号**（拿到就能定论）：

| 信号 | 说明什么 |
|---|---|
| 第 5 步成功产出 Markdown | L2 抓取链路在真机成立 |
| 第 6 步拿到二维码 | 微信登录接口可用；二维码交付方案成立 |
| 第 7 步列出文章 | **`appmsgpublish` 接口还活着 —— 方案成立** |

三个都过 = 整条链路端到端打通，可以开始用了。
哪一个不过 = 我们精准知道该修哪里。

## 附：当前已知的边界（避免误判成 bug）

- **产物默认落在 dsh 的启动目录**，不是你在界面上选的工作区。这是已知行为，
  工具会主动提示你改（第 4 步）。原因是这个版本的宿主没把会话工作目录暴露给插件。
- **不需要登录**：第 1~5、8 步。**需要登录**：第 6~7 步。
- **付费文章 / 视频图片类文章**抓不到完整正文 —— 这是微信的限制（不是登录问题），
  插件会明确告诉你"内容可能不完整"。
- **批量抓取目前只有整体上限（30 分钟），没有逐篇超时** —— 单篇卡住会拖住整批。
  要根治得给 `spider-claw` 加 `signal` 支持。
